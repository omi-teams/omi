## Goal
Skills load only when a task declares them. Nothing is listed in always-on context except a one-line-per-skill catalog.

## Acceptance criteria
- [ ] Skills live in `.omi/skills/<group>/<id>/SKILL.md`, outside `.claude/skills`, so the harness does not auto-list them. `omi init` creates the folder.
- [ ] `.omi/skills/CATALOG.md`: one line per skill: id, when to use, estimated tokens (bytes/4). It is generated by `python -m omi skills` (no hand editing).
- [ ] Task frontmatter gets `skills: [id, ...]` (template updated). Unknown id, or a skill missing from the catalog, fails.
- [ ] Budget enforced by `python -m omi` when a task starts: at most 3 skills and 6000 tokens in total (SKILL.md plus declared references); one skill at most 2000 tokens. Over budget fails with the numbers; only the PO can raise it (config value, recorded in decisions).
- [ ] `omi worker` and the reviewer prompt pass only the declared skill paths, never the catalog or other skills.
- [ ] The Coordinator picks skills from the catalog at planning time (omi-task skill updated); AGENTS.md grows by at most 3 lines.
- [ ] Tests: budget pass/fail, unknown id, catalog generation; `python tests/test_omi.py` passes.

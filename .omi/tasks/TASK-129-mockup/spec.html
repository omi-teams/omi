UI spec · TASK-129

Proposed design contract for Coordinator to record in the task. Pending PO approval; static HTML only, no app implementation.

Scope and layout

One changed screen: project dashboard. Retain existing omi brand, Vietnamese UI, vanilla HTML/CSS/JS, system fonts, theme and dashboard sections. Place the filter panel immediately before the task tree; both tree and Kanban consume its results. Project overview, PO queue, summary totals, plans, activity, decisions and usage remain project-wide and explicitly outside filtering. No new dependencies or assets.

Reference desktop 1280 px, phone 390 px; support 320 px and 200% zoom. Main max-width 1280 px, desktop gutters and section gaps 24 px. Filter row: search 2fr, four native selects 1fr each; between 768–1000 px search spans two columns and selects form two columns; below 768 px everything stacks with 16 px gutters. No horizontal scrolling, truncated essential text, fixed-height panels or sticky filter bar. Existing task page needs no new visual screen.

Tokens and components

Use established system-ui, -apple-system, Segoe UI, sans-serif; mono ui-monospace, Cascadia Mono, Consolas, monospace. Body 15/1.5, help 13, labels 13/600, h1 28/600 (phone 24), h2 19/600. Heading tracking −.025em; tabular numbers. No font downloads. Spacing 4, 6, 8, 12, 16, 20, 24, 48 px; panel/control/card radius 12/6/7 px. Controls minimum 44 px high; visible labels; panel padding 20 px, phone 16 px.

Light: background #f6f6f4, surface #ffffff, text #1f2421, muted and control border #5f6661, decorative divider #e4e3df, accent/focus #0f6e6e, chip #0f6e6e on #e2f3f2, error #9b343b. Dark: #191e1c, #232a26, #e3e9e5, #a9b6ad, #3b443e, #78c9c2, chip #78c9c2 on #193e40, error #f6b5b9 respectively. Theme follows OS. Existing status/type badges keep existing app token pairs and text labels. No new semantic status colors.

Focus 3 px accent with 3 px offset on links, buttons, search and selects. Hover uses accent border/text or link underline; pressed button scale .98. Transform/opacity transitions only, 220 ms cubic-bezier(.32,.72,0,1); reduced motion removes transitions and press transform. No animated loading shimmer. Disabled uses muted text on background, no opacity reduction.

Filter contract and copy

Search label “Tìm ID hoặc tiêu đề”; placeholder “VD: TASK-129 hoặc board”. Help “/ để tìm kiếm · Esc xóa từ khóa · Các bộ lọc kết hợp với nhau.” Search compares trimmed case-insensitive substring against ID OR title, preserving diacritics. Each of four single-select filters combines with search using AND; default is all. No Apply button, no server fetch on edits; use the complete currently loaded project data.

Labels: “Trạng thái”, “Loại”, “Kế hoạch”, “Vai trò”. Defaults: “Tất cả trạng thái”, “Tất cả loại”, “Tất cả kế hoạch”, “Tất cả vai trò”. Status uses resolved task.status, not workflow phase: planned “Chưa bắt đầu”, in-progress “Đang làm”, review “Đang review”, blocked “Bị chặn”, done “Xong”. Types: milestone, epic, fr, nfr, task with existing display labels. Plan/role options are sorted distinct exact metadata values from all loaded tasks, never narrowed by other filters. Include “Không có kế hoạch” and “Chưa có vai trò” for absent fields; absent type means task. Display raw plan IDs and role names without interpreting markup. No metadata inheritance from ancestors.

Match each node against its own fields; retain ancestors needed to reach matching descendants and label those ancestors “Ngữ cảnh; không khớp bộ lọc”. Open these paths while filtering, restore prior disclosure state after clearing. A matching parent does not make descendants match. Kanban only includes matching leaves, grouped by existing nine workflow phases in established order; counts and empty-phase disclosure reflect filtered leaves. Never promote a filtered-out child’s parent to a leaf. Result status “N / T công việc khớp · L task lá trên Kanban” counts matches before adding contextual ancestors. For parent-only results show “Không có task lá khớp bộ lọc trên Kanban.” even though the tree has results.

“Đặt lại bộ lọc” clears query and four filters; disabled only in the default state. An empty-result reset remains enabled. Preserve focus on the initiating control; after clearing via an empty-result reset that disappears, move focus to search. “Sao chép liên kết” copies the absolute current dashboard URL, stays on the page and announces “Đã sao chép liên kết.” On failure display the labeled read-only selectable URL and “Không sao chép được. Chọn và sao chép liên kết bên dưới.” Never require Clipboard API for manual sharing.

URL, navigation and keyboard

Hash query proposal: #/p/omi?q=board&status=in-progress&type=task&plan=PLAN-007&role=omi-agent-engineer. Parameters belong after the dashboard route inside the hash. Use percent encoding for every value; canonical order q,status,type,plan,role; omit all/default and blank values; missing plan or role uses reserved value ~none (encode a literal metadata value beginning ~ with an extra ~). Unknown keys ignored; repeated keys use first value; invalid enum, malformed encoding or removed plan/role options reset the affected field only and show “Một số bộ lọc không còn khả dụng đã được bỏ qua.” with polite announcement. Never throw away the project route.

Restore controls and results before presenting a linked view; refresh preserves filters and reconciles removed options. Search updates locally as input changes; use replaceState for query edits, pushState for committed select/reset changes. Back/Forward restores hash state without refetching loaded project data, moving focus or scrolling to top. Route parsing must split hash path/query before matching existing routes. Preserve view parameters when opening a task and in the return-to-project link; task detail ignores these parameters visually. Cost, inbox and project index keep their existing routes.

Card links in these static mockups point here to explain the handoff; engineer must retain actual task routes. Task opening and its return link carry the current filter query. This spec adds no task-detail controls.

/ focuses search only on dashboard and outside editable elements, selects, composing text or modified shortcuts; prevent inserting /. Search exposes aria-keyshortcuts="/". Esc in search clears query only, keeps four filters, retains focus and updates URL; elsewhere it does nothing. Tab order: search → status → type → plan → role → reset (when enabled) → copy → tree → Kanban. Native select arrow keys remain native. Result changes do not recreate focused inputs or move focus; polite result announcements coalesced after 250 ms while typing. No submit/reload on Enter.

States and accessibility acceptance

See states.html for default, no matches, no project tasks, initial loading/disabled, initial load failure, stale-data refresh failure, focus, copy success/failure and invalid link notice. During initial loading preserve hash values, disable data-dependent controls and share/reset, set results region aria-busy=true, use static aria-hidden skeletons and “Đang tải…”. After first-load failure show “Không tải được dữ liệu. Thử làm mới.” and enabled “Thử lại”; filters remain disabled until success. Refresh keeps previous results and filters usable; disable only refresh while its request is pending. Failure announces “Không làm mới được. Đang hiển thị dữ liệu lần tải trước.” and preserves the view.

No matches: “Không tìm thấy công việc phù hợp.” + “Thử từ khóa khác hoặc đặt lại bộ lọc.” and reset; suppress empty tree/phase grids. Empty dataset: “Chưa có công việc trong dự án này.” + “Board chỉ đọc. Thêm task trong repo rồi làm mới.”, default reset disabled. No-results UI is not an error. Error messages are inline, no dialog/alert(). Copy stays enabled for any successfully loaded view including no results.

Semantic header/nav/main; one h1, ordered headings, native labels/inputs/selects/buttons/details, article cards with real task links. Skip link reaches main. Use textContent for all state-derived strings and option labels. Result and copy feedback role=status (polite); blocking fetch failure role=alert, no duplicate live announcements. Provide disabled explanation in visible text. Ensure controls and focus ≥3:1, all normal text ≥4.5:1; no color-only meaning. Maintain 44 px control and 24 px link targets, logical DOM order, visible unclipped focus, wrapping at 320 px/200%, no positive tabindex or keyboard traps. Browser verification is pending; static specifications are not evidence of runtime compliance.

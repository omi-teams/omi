UI spec · Layout, typography & tokens

Keep existing omi branding, Vietnamese UI and vanilla HTML/CSS/JS stack. No new dependencies, external assets, fonts or network. Examples are labeled fixture data, never changes to task content.

Desktop reference: 1280 px. Main max-width 1280 px, 24 px gutters and section gaps. App navigation marks the current page with aria-current=page; the spec link in these files is only a mockup review aid. Project list → project dashboard → task detail. Task detail has main content plus 300 px metadata sidebar. Below 768 px: single column, 16 px gutters, metadata follows task content. Phone references cap at 390 px and shrink to 320 px; workflow must read at 360 px. No clipped labels, fixed content heights or page horizontal scrolling.

System display/body: system-ui, -apple-system, Segoe UI, sans-serif; ui-monospace for IDs/data. H1 28/35 px desktop, 24/30 px phone; H2 19/24 px; body 15/22.5 px; metadata 13/19.5 px; chips 12/18 px. Headings 600, supporting emphasis 500, tabular numerals, body width 65ch.

Spacing scale: 4, 8, 12, 16, 20, 24, 32, 48, 64 px. Radius: panels 12, columns 8, cards 7, controls 6, badges 5 px. Flat surfaces, no shadows. Background/surface/text/muted/border/control/accent/track light and dark tokens are the inline CSS custom properties in each mockup. Theme follows OS preference; no theme control is added.

Phase/type foreground and background pairs appear below. Stored statuses map planned → planned, in-progress → working, review → review, blocked → blocked, done → done. Each type has a distinct pair. Teal is the action accent; semantic colors are categorical. Every badge includes text; workflow uses ✓, numbers and “Hiện tại”.

UI spec · Hierarchy, phase & data

Use TASK-124 type, parent, children and top-level derived status; never replace derived parent status with frontmatter status. Roots include standalone task leaves and sort by ID; children retain API order. Native details/summary expand parents; default milestone, epic and active FR/NFR open, completed/blocked branches closed as illustrated. Retain disclosure state through polling within a project. Parent summary toggles; leaf links navigate.

Parent type badge, derived chip labeled “tổng hợp”, native progress and visible done/total count direct children using derived status. Counts and progress stay visible inside the summary even when collapsed. Nested completion counts once per direct child. All done → Xong; any blocked → Bị chặn; all planned → Chưa bắt đầu; otherwise Đang làm. No ARIA tree or custom arrow-key behavior.

Kanban, project summary counts and completion statistics show task leaves to avoid counting parents twice; tree shows all items. Derive leaf statistics from existing project kanban tasks, since API task_counts includes parents. Project-list counts may be computed from existing per-project GET responses; do not request new API fields. Parent plans retain API plan counts and must label the counted unit accurately; fixture PLAN-007 contains four task leaves.

Group leaves by API phase.key and use phase.label in this order: Chưa bắt đầu, Lên kế hoạch, Thiết kế, Đang làm, Đang review, Đang QA, Chờ PO, Bị chặn, Xong. Desktop three columns wrap in phase order; phone one column. Nonempty columns show all cards; empty phases live in one native disclosure listing each phase and zero. Expanded disclosure shows “Chưa có task.” for every empty phase.

Cards show ID, title link, type badge, phase chip, “bước N/M · step-id” and “Vòng review: R”. Null step index → “bước ?/M”; null review_round → “Vòng review: —”. Unknown count → “bước ?/?”. R comes only from API review_round. Parent detail uses derived status as primary chip and labels its separate workflow “Quy trình riêng”; no guessed aggregate phase.

Workflow renders every API workflow_steps node in order; gate=po always labeled “PO duyệt”. Node names are step IDs. Desktop directed row; below 768 px a vertical list with downward arrows. For longer workflows, use vertical layout whenever labels cannot fit; never truncate labels. Arrows are decorative. Current node uses aria-current=step and “Hiện tại”; preceding nodes ✓ Xong, later nodes numbered Chưa bắt đầu. Status done overrides index: every node, including the final accept, ✓ Xong, no current node. Unknown step: no current/completion guesses, “Không xác định bước hiện tại.” Empty definition: “Chưa có định nghĩa quy trình.”

Task retains goal, acceptance criteria, Checkpoint, steps, reports and metadata. Reports: native disclosure, latest open. Usage: labeled definition list at every width, each role/output/duration stacked with totals visible; no scroll container. Wrap long IDs, scopes and model names. Keep source, PO waiting, plans, activity and decisions. PO entries link to task details; board stays read-only. Dynamic content must use textContent only.

UI spec · States, behavior & accessibility

Initial loading: title and static skeleton, “Đang tải…” role=status, main aria-busy=true. Refresh keeps existing content, disables only refresh and changes its label to “Đang tải…”. Success reenables and announces update time. Error retains old data when present; initial error displays no invented data, inline role=alert message + Thử lại. Retry uses existing refresh behavior. Stale source shows last fetched time. Polling retains disclosure/focus/scroll and does not announce the full dashboard; route changes focus H1.

One H1, ordered headings, nav/main/aside landmarks, Vietnamese lang and unique page title, skip link. Links navigate, buttons act. Native summary works with Enter/Space; Tab order follows reading order, no positive tabindex or traps. 3 px accent focus ring, 3 px offset; no sticky header obscures focus. Controls/summary ≥44 px; inline links ≥24 px. Text contrast ≥4.5:1, control boundaries/focus ≥3:1. Visible count plus specific accessible progress name. All information has labels beyond color. No forms added.

No automatic motion. Interactive transform/opacity transitions 220 ms cubic-bezier(.32,.72,0,1); press scale .98. Reduced-motion disables transitions and press transform. Permit 200% zoom and pinch zoom, reflow to 320 px. Empty states use exact copy illustrated below. Native disabled controls retain labels, navigation stays available.

Buttons are illustrative and inert in mockups; native disclosures, skip links and local links work. Source inspection and calculated contrast only; browser focus, zoom, keyboard and viewport testing are deferred to QA after PO approval.

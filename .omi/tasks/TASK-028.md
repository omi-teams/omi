## Goal
Roles are prompt files in `.omi/agents`, loaded only when a task names them. `.claude/agents` is removed so the harness lists no agents.

## Acceptance criteria
- [ ] `.omi/agents/<role>.md` with frontmatter `role, model, effort, access (write|read), skills (default ids), summary`. `engineer` and `reviewer` are moved here unchanged in behaviour; `.claude/agents/*` and their template copies are deleted.
- [ ] `.omi/agents/CATALOG.md`: one line per role (role, when to use, access, model/effort), generated by `python -m omi agents`.
- [ ] Task frontmatter gets `role:` (default `engineer`); unknown role fails. The role's default skills plus the task's `skills:` count against the TASK-021 budget.
- [ ] `python -m omi run <role> <TASK-ID>` runs the role for Claude Code and Codex alike (Codex: `codex exec -m <model> -c model_reasoning_effort=<level>`), with model and effort from the frontmatter.
- [ ] `access: write` roles run in the Docker worker on the task worktree (as `omi worker` does now). `access: read` roles run in Docker with the worktree mounted read-only and no network beyond the model API; no host fallback when Docker is down (stop and tell the PO).
- [ ] The reviewer is a fresh instance on every run and checks the diff against the acceptance criteria (behaviour as today).
- [ ] Before any read role is started on a diff, `omi` runs the deterministic checks (tests, scope check, `omi skills --check`, `omi workflows --check` when present) and does not start the role while one fails; the failure is reported instead. This is how token use is saved on diffs a script can reject.
- [ ] omi-task skill, AGENTS.md (Roles section, at most 3 added lines) and README updated; `python tests/test_omi.py` passes, including a test that a read role cannot write.
